# Optymalizacje codegen: Motorola 6809

Plan 47 jest zamknięty. Cel jest big-endian, domyślnie używa ABI v1 (`cc_argN`/`cc_ret`), a opt-in ABI v2 przekazuje argumenty W2 z pozycji 0–2 w X/Y/U; W1 i dalsze argumenty pozostają w pamięci, wynik nadal wraca przez `cc_ret`. Wskaźnik X i DP ustawione przez crt0 na `$00`.
Emisja dziedziczy większość prymitywów 6800; nazwy mnemoników i operacje startowe są dostosowane do 6809.

| Ficzer | Status | Dowód / uwagi |
| --- | --- | --- |
| Rejestry komórek (alokator) | brak | `CellRegisters`/`CellPairs` puste; model CPU opisuje rejestry, ale alokacja komórek nie jest włączona |
| ParamAlias (liście → `cc_argN`) | brak | ParamAlias pozostaje wyłączony dla big-endian |
| Argumenty W2 w X/Y/U (ABI v2) | częściowe | Opt-in, pierwsze trzy pozycje; W1 i dalsze argumenty pamięciowe; pośrednie wywołanie przez `cc_fp`; runtime helpery ABI v1 |
| Wynik w rejestrze | brak | Wynik wraca przez `cc_ret`; prototyp wyniku w D rósł w wielu wierszach goldenów i został odrzucony |
| Kopie słów (`TryMoveWord`) | zrobione | Dziedziczone z 6800: X przenosi słowo big-endian przez pamięć |
| Arytmetyka słów w rejestrach | brak | Łańcuch bajtów przez A; bez akumulatorowego `TryAddWord` |
| Porównania ze znakiem (forma zerowa) | zrobione | `TryBranchZeroSigned`, używa `LDA`/`ORA` i relaksowanych skoków |
| Porównania ze znakiem (forma ze stałą) | brak | Stałe korzystają z ogólnej ścieżki legalizera |
| Peephole `Tidy` | brak | Brak reguł specyficznych dla 6809 |
| Relaksacja skoków | zrobione | `BranchRelaxer.Apply`; lokalne skoki warunkowe skracane, gdy są w zasięgu |
| Tail call | brak | Wołania kończą się standardowym `JSR`/`RTS` |
| Ramki (`Saved`, push/pop) | częściowe | Bajty przez `PSHS A`/`PULS A`; brak specjalizowanych operacji słowa |
| Wskaźniki | zrobione | `PtrSetup`/`PtrLoad`/`PtrStore` przez X; brak `IndexFusion` |
| Strona bezpośrednia | częściowe | DP=$00 i pula ZP; `TryStep` wymusza direct dla `INC/DEC/TST` komórek na stronie |
| Kopiowanie bloków | zrobione (pętla software) | `ICopyLoop`: X/Y z auto-inc, U jako licznik; nie jest to rozkaz blokowy |
| Strength reduction | częściowe | Mnożenie przez stałą obsługuje wspólny legalizer; brak haków rejestrowych |
| `switch uchar` → 1 B | zrobione | Wspólne zwężenie w `LowerSwitch` |
| DJNZ / RST | brak | Brak odpowiedników używanych przez optymalizacje Z80 |
| ABI v2 (rejestry) | częściowe | Opt-in argumenty W2 w X/Y/U; ABI v1 pozostaje domyślne |

## Baza i kolejne prace

- Poprawność: `TargetMatrixTests` (192 przypadki), `VRegMatrixTests`/`CpuModelAllocatorTests` oraz testy interpreterów 6809.
- Rozmiary CODE: tabela [target-sizes.md](../target-sizes.md); ścieżka VReg: [vreg-sizes.md](../vreg-sizes.md).
- `args_many` ABI v1→v2: 190→173 B w Cell i VReg. Pętla kopiująca dwa wskaźniki: 174→154 B w Cell i 158→138 B w VReg.
- Wynik W≤2 w D odrzucono po pomiarze: prototyp zwiększał m.in. `05_calls` 441→457 B i `25_longlong` 10901→10965 B. Dalsze warianty i pomiary: [plan 47](../plans/47-cpu-6809-opt.md).
- TFR do ustawienia drugiego wskaźnika odrzucono: `LDY direct` ma 3 B, a `LDX direct` + `TFR X,Y` ma 4 B.
- Weryfikacja: `dotnet build -warnaserror` oraz pełna suita (3502 testy) zielone; goldeny target/VReg bez wzrostu; leaf i recursion fuzz 60/60 zielone. Generator leaf fuzz emituje jawne rzutowania przy przypisaniach/return oraz deklaruje licznik pętli tylko wtedy, gdy go używa.
